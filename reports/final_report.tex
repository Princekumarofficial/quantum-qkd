\begin{abstract}
\noindent
This report documents the complete design, implementation, and simulation-based experimental evaluation of \textbf{ChaQra}, a full-stack discrete-event Quantum Key Distribution (QKD) network simulator. The project spans six weeks of progressive development, beginning with framework evaluation and concluding with a deployed, interactive web-based simulation tool.

The simulator is built on the \textbf{SeQUeNCe} quantum network simulation framework and implements two complementary runtime-selected engines: (1) a direct single-hop BBM92 simulation using a custom \texttt{TrackedSPDCSource} that correctly routes entangled photon pairs through lossy fiber \texttt{QuantumChannel} components, and (2) a multi-hop quantum repeater engine that performs entanglement generation and swapping across arbitrary user-defined network topologies using a Breadth-First Search path discovery algorithm.

The system addresses four non-trivial integration issues encountered while using the SeQUeNCe framework—specifically the SPDC channel bypass issue, Poisson zero-emission dropouts, \texttt{FreeQuantumState} non-subscriptability, and a 4-dimensional to 2-dimensional state-collapse matrix mismatch—each of which is documented with root cause analysis and the applied fix.

Simulation-based experimental evaluation across multiple scales confirms the canonical quantum repeater advantage: over a 30 km span, a 4-hop repeater network yields a longer sifted key (135 bits vs.\ 110 bits) and a lower QBER (5.19\% vs.\ 7.27\%) than a direct 2-hop link. All configurations evaluated satisfy the 11\% QBER security threshold for BBM92. A full-featured interactive interface—featuring drag-and-drop topology editing, real-time GIS geographic mapping with automatic Haversine distance computation, per-trial simulation playback, and optical component schematics—is deployed at \url{https://quantum-qkd-taupe.vercel.app/}.
\end{abstract}

\section{Introduction}
% =============================================================================

Quantum Key Distribution (QKD) is a cryptographic technique that exploits the fundamental laws of quantum mechanics—specifically, wave-function collapse upon measurement and the no-cloning theorem—to guarantee information-theoretically secure key exchange between two parties. Unlike classical cryptographic schemes whose security rests on computational hardness assumptions, QKD provides unconditional security: any eavesdropping attempt is detectable through measurable disturbances to the quantum channel.

The BBM92 protocol \cite{BBM92Paper}, proposed by Bennett, Brassard, and Mermin in 1992, is the entanglement-based analogue of the prepare-and-measure BB84 protocol. Rather than one party preparing and transmitting qubits, a central Spontaneous Parametric Down-Conversion (SPDC) source distributes maximally entangled photon pairs $|\Phi^+\rangle = \frac{1}{\sqrt{2}}(|HH\rangle + |VV\rangle)$ to two communicating parties (Alice and Bob). Both parties independently measure their photons in randomly chosen polarization bases. The quantum correlations of the Bell state guarantee that whenever they happen to choose the same measurement basis, their results are perfectly correlated—forming the raw material for a shared secret key.

Simulating QKD networks under realistic physical conditions is essential both for protocol research and for engineering network deployments. Discrete-event simulation (DES) is the standard modeling paradigm for this purpose: the state of the network evolves only in response to discrete events (photon emissions, channel losses, detector clicks, classical message arrivals), allowing complex multi-node topologies to be modeled efficiently on classical hardware.

\textbf{ChaQra} (Quantum) is the simulation system developed over this project. It provides:
\begin{itemize}
    \item A discrete-event simulation backend (Python/FastAPI) built on the SeQUeNCe \cite{SequenceTutorial} framework, supporting both direct BBM92 and multi-hop quantum repeater topologies.
    \item A web-based interactive frontend (React/Vite) with drag-and-drop topology design, real GIS coordinate mapping, per-trial animation, and node-level optical hardware schematics.
    \item End-to-end simulation-based experimental evaluation on realistic network configurations with documented physical channel parameters and measured sifted key outputs.
\end{itemize}

The remainder of this report is organized chronologically by development phase, followed by a comprehensive technical description of the final system architecture, simulation results, and appendices covering the high-level theoretical foundations and the full implementation.

\section{Week 2 --- Discrete Event Simulation Foundations}
% =============================================================================

\subsection{Objective}

The objective of Week 2 was to master the SeQUeNCe DES execution kernel and prototype the elementary network building blocks required for subsequent quantum protocol simulations.

\subsection{The DES Execution Model}

Discrete Event Simulation models a system as a sequence of state-changing events, each occurring at a precise simulation timestamp. The SeQUeNCe DES kernel is built around three core abstractions:

\begin{itemize}
    \item \textbf{\texttt{Timeline}}: Maintains a min-heap priority queue of scheduled events ordered by simulation time. \texttt{tl.run()} dequeues and executes events in chronological order until the queue is empty or a stop-time is reached.
    \item \textbf{\texttt{Event(t, process)}}: Represents a state-change action to be fired at simulation time $t$.
    \item \textbf{\texttt{Process(obj, 'method', args)}}: Encapsulates a deferred method call on a simulation object, executed when the event fires.
\end{itemize}

This abstraction allows complex time-ordered interaction chains to be specified declaratively without manual time-tracking logic.

\subsection{Store Open/Close Event Loop}

A practical demonstration was implemented as a retail store that opens and closes on a fixed 12-unit cycle. This exercise introduced cascading event scheduling—each event schedules its successor—and the SeQUeNCe logging framework:

\begin{lstlisting}[language=Python, caption={Self-scheduling DES event loop (DES/des.py)}]
class Store:
    def __init__(self, tl: Timeline):
        self.opening = False
        self.timeline = tl

    def open(self) -> None:
        if self.timeline.now() >= 60:
            self.timeline.stop()
        log.logger.info('Store being opened.')
        self.opening = True
        process = Process(self, 'close', [])
        event = Event(self.timeline.now() + 12, process)
        self.timeline.schedule(event)

    def close(self) -> None:
        if self.timeline.now() >= 60:
            self.timeline.stop()
        log.logger.info('Store being closed.')
        self.opening = False
        process = Process(self, 'open', [])
        event = Event(self.timeline.now() + 12, process)
        self.timeline.schedule(event)
\end{lstlisting}

\subsection{Quantum Network Component Primitives}

Beyond the DES kernel, the SeQUeNCe framework provides pre-built quantum hardware models. The following components were studied and prototyped this week:

\begin{itemize}
    \item \textbf{\texttt{Memory}}: Quantum memory with configurable \texttt{fidelity}, \texttt{coherence\_time} (s), \texttt{efficiency}, \texttt{frequency} (Hz), and \texttt{wavelength} (nm).
    \item \textbf{\texttt{QSDetectorPolarization}}: Hardware single-photon polarization detector with configurable detection efficiency and dark count rate.
    \item \textbf{\texttt{QuantumChannel}}: Fiber channel applying Poisson-distributed photon loss (parameterized by attenuation in dB/m) and random polarization state flipping (parameterized by \texttt{polarization\_fidelity}).
    \item \textbf{\texttt{ClassicalChannel}}: Ideal classical message channel with configurable propagation delay.
    \item \textbf{\texttt{Protocol}}: Abstract base class for node-local state machines that exchange typed \texttt{Message} objects over classical channels.
\end{itemize}

A bidirectional ping-pong protocol (\texttt{hardware-module/pingpong.py}) was implemented to validate classical channel communication between two nodes, confirming the message-passing architecture that would later be used for basis sifting in BBM92.

\section{Week 3 --- Entanglement Management and the Barrett-Kok Protocol}
% =============================================================================

\subsection{Objective}

The objective of Week 3 was to understand the theoretical barrier to long-distance quantum communication and to implement the entanglement generation mechanism at the heart of quantum repeater networks.

\subsection{The Fundamental Problem: Exponential Fiber Attenuation}

Photon transmission probability over a fiber of length $L$ (m) with attenuation coefficient $\alpha$ (dB/m) is:
\begin{equation}
    P_{\text{trans}}(L) = 10^{-\alpha L / 10}
    \label{eq:beer_lambert}
\end{equation}
For standard telecom fiber ($\alpha \approx 0.0002$ dB/m at 1550 nm), over $L = 100$ km, $P_{\text{trans}} \approx 10^{-2}$—a 99\% loss rate. Classical repeaters amplify signals by measuring and retransmitting, but this is forbidden for quantum states by the \textbf{No-Cloning Theorem}: a general unknown quantum state $|\psi\rangle$ cannot be copied. Measuring for amplification collapses the superposition irreversibly.

\subsection{The Barrett-Kok Protocol}

The Barrett-Kok protocol provides a solution: instead of transmitting quantum states across long distances, entanglement is generated between adjacent short-distance nodes using heralded photon pair measurement at a central Bell State Measurement (BSM) station. The protocol proceeds in three steps.

\subsubsection{Step 1: Spin-Photon Entanglement}
Each node initializes its quantum memory in superposition $|+\rangle = \frac{1}{\sqrt{2}}(|0\rangle + |1\rangle)$. A laser pulse causes conditional photon emission from $|1\rangle$ only:
\begin{equation}
    \frac{1}{\sqrt{2}}(|0\rangle + |1\rangle) \xrightarrow{\text{laser}} \frac{1}{\sqrt{2}}\bigl(|0\rangle|\text{vac}\rangle + |1\rangle|\text{photon}\rangle\bigr)
\end{equation}
The emitted photon carries information about the qubit state—they are now entangled.

\subsubsection{Step 2: Path Erasure at the BSM Station}
Photons from nodes $A$ and $B$ travel to a central 50:50 beam splitter. A detector click on either output port projects the joint state. The key insight is that a single click does \emph{not} identify which node emitted the photon—path information is erased. This enforces the memory-photon entanglement to collapse the two remote memories into the Bell state:
\begin{equation}
    |\Psi^+\rangle_{A,B} = \frac{1}{\sqrt{2}}\bigl(|0\rangle_A|1\rangle_B + |1\rangle_A|0\rangle_B\bigr)
\end{equation}

\subsubsection{Step 3: The 50\% Fundamental Limit}
Linear-optics BSMs using beam splitters and photo-detectors can distinguish only two of the four Bell states—the antisymmetric states $|\Psi^+\rangle$ and $|\Psi^-\rangle$ (via Hong-Ou-Mandel anti-bunching)—while the symmetric states $|\Phi^\pm\rangle$ produce identical detector signatures (two clicks, same port). Since all four Bell states occur with equal probability of 25\%, the maximum success probability for any linear-optics BSM is:
\begin{equation}
    P_{\text{BK success}} \leq 50\%
\end{equation}
Simulation across 1000 independent protocol attempts confirmed this bound: approximately 500 successes and 500 failures.

\subsection{Entanglement Swapping: Extending the Network}

Once short-distance entangled links $(A, R_1)$ and $(R_2, B)$ are established at an intermediate repeater $R$, the entanglement range can be extended to the full $(A, B)$ span without any direct photon exchange:

\begin{equation}
\begin{split}
    |\Psi\rangle_{\text{total}} &= |\Phi^+\rangle_{A,R_1} \otimes |\Phi^+\rangle_{R_2,B} \\
    &= \frac{1}{2}\Big[
        |\Phi^+\rangle_{R_1,R_2}|\Phi^+\rangle_{A,B}
        + |\Phi^-\rangle_{R_1,R_2}|\Phi^-\rangle_{A,B} \\
    &\quad\quad\quad\;
        + |\Psi^+\rangle_{R_1,R_2}|\Psi^+\rangle_{A,B}
        + |\Psi^-\rangle_{R_1,R_2}|\Psi^-\rangle_{A,B}
    \Big]
\end{split}
    \label{eq:swapping}
\end{equation}

The repeater $R$ performs a local BSM on $R_1$ and $R_2$, projecting the $A$-$B$ pair into the corresponding Bell state. The BSM outcome (2 classical bits) is sent to $B$ over a classical channel, which applies the appropriate Pauli correction to recover the target state $|\Phi^+\rangle_{A,B}$.

\section{Week 4 --- BBM92 Protocol: Full Implementation}
% =============================================================================

\subsection{Objective}

The objective of Week 4 was to implement a complete, end-to-end BBM92 QKD protocol pipeline and validate it against theoretical predictions under realistic channel parameters.

\subsection{Protocol Description}

The BBM92 protocol \cite{BBM92Paper} distributes quantum key bits by exploiting the correlations of polarization-entangled photon pairs. The five protocol stages are:

\begin{enumerate}
    \item \textbf{Entangled pair distribution}: A central SPDC source emits photon pairs in the $|\Phi^+\rangle = \frac{1}{\sqrt{2}}(|HH\rangle + |VV\rangle)$ Bell state. One photon is directed to Alice, the other to Bob, via separate quantum fiber channels.
    \item \textbf{Independent basis selection}: Alice and Bob each independently and uniformly at random choose a measurement basis: $Z$-basis $\{|H\rangle, |V\rangle\}$ (basis code 0) or $X$-basis $\{|+\rangle, |-\rangle\}$ (basis code 1). The key property of $|\Phi^+\rangle$ is that same-basis measurements always produce identical outcomes, while different-basis measurements produce uncorrelated results.
    \item \textbf{Polarization measurement}: Each party measures its photon and records the binary outcome.
    \item \textbf{Classical basis sifting}: After all photons have been measured, Alice and Bob publicly broadcast their basis choices over an authenticated classical channel. Only trials where both chose the same basis are retained; the rest are discarded. This sifting retains $\approx 50\%$ of trials in the ideal case.
    \item \textbf{QBER estimation}: A random sample ($\approx 15\%$) of the sifted key is publicly compared. The fraction of disagreements is the Quantum Bit Error Rate:
    \begin{equation}
        \text{QBER} = \frac{\sum_{i \in \text{sample}} b_{A,i} \oplus b_{B,i}}{|\text{sample}|} \times 100\%
        \label{eq:qber}
    \end{equation}
    If QBER $\leq 11\%$, the channel is classified as secure and the protocol proceeds to error correction and privacy amplification.
\end{enumerate}

\subsection{SeQUeNCe Implementation}

The simulation was implemented using three custom classes extending the SeQUeNCe library, plus a classical post-processing sifting stage.

\subsubsection{TrackedSPDCSource}

SeQUeNCe's built-in \texttt{SPDCSource} emits photon pairs with Poisson-distributed multiplicity at rate $f$ Hz. Each emission invokes an internal \texttt{send\_photons()} method. Two critical integration issues were identified during development:

\begin{description}
    \item[Bug 1 --- Channel bypass]: \texttt{SPDCSource.send\_photons()} calls \texttt{Process(receiver, "get", [photon])} directly on registered receiver objects, bypassing the \texttt{QuantumChannel} instance. No attenuation loss or polarization noise is applied. This caused QBER to always read 0\%.
    
    \textit{Fix}: Subclassed as \texttt{TrackedSPDCSource} and overrode \texttt{send\_photons()} to call \texttt{owner.send\_qubit(dst, photon)}, which internally invokes \texttt{QuantumChannel.transmit()}, correctly applying fiber loss and polarization flipping before scheduling photon arrival.
    
    \item[Bug 2 --- Poisson zero-emission dropouts]: With the default \texttt{mean\_photon\_num} $= 1.0$, the Poisson distribution gives $P(0\text{ photons}) = e^{-1} \approx 37\%$, silently voiding 37\% of trials.
    
    \textit{Fix}: Set \texttt{mean\_photon\_num} $= 10.0$, reducing the empty-trial probability to $e^{-10} \approx 5 \times 10^{-3}\%$.
\end{description}

Additionally, each emitted photon was stamped with a unique trial index (\texttt{photon.trial = trial\_index}) so that measurement results from Alice and Bob could be accurately matched in a global \texttt{SIMULATION\_TRIALS} dictionary.

\begin{lstlisting}[language=Python, caption={TrackedSPDCSource: trial tagging and channel routing (backend/main.py)}]
class TrackedSPDCSource(SPDCSource):
    def __init__(self, *args, **kwargs):
        super().__init__(*args, **kwargs)
        self._trial_index = 0
        self.channels = (None, None)

    def send_photons(self, time, photons):
        trial = self._trial_index
        self._trial_index += 1
        for ph in photons:
            ph.trial = trial
            ph.pair_id = trial
        ph_alice, ph_bob = photons
        qch_a, qch_b = self.channels
        if qch_a and qch_b:
            self.timeline.schedule(Event(int(round(time)),
                Process(self.owner, 'send_qubit', [qch_a.receiver, ph_alice])))
            self.timeline.schedule(Event(int(round(time)),
                Process(self.owner, 'send_qubit', [qch_b.receiver, ph_bob])))
\end{lstlisting}

\subsubsection{SimParticipantProtocol}

Each endpoint node runs a \texttt{SimParticipantProtocol} that intercepts arriving photons via a \texttt{PhotonTap} entity, randomly selects a measurement basis, and records the outcome:

\begin{lstlisting}[language=Python, caption={Endpoint measurement protocol}]
def received_message(self, src: str, msg: Message):
    trial  = msg.payload.get('trial')
    photon = msg.payload.get('photon')
    if trial is None:
        return
    basis = self.rng.randrange(2)          # 0 = Z-basis, 1 = X-basis
    info  = SIMULATION_TRIALS.setdefault(trial, {})
    info[f'{self.node_id}_basis'] = basis

    # Physical hardware detector (collapses 4D joint state to 2D)
    try:
        self.qsdet.get(photon, src=src)
    except Exception:
        pass

    # Logical measurement (operates on now-collapsed 2D state)
    basis_mat = polarization['bases'][basis]
    try:
        res = Photon.measure(basis_mat, photon, self.rng)
    except Exception:
        res = None         # fallback: no detection

    if res is not None:
        info[f'{self.node_id}_result'] = res
\end{lstlisting}

Two additional integration issues were identified during development of \texttt{SimParticipantProtocol} with the full backend:

\begin{description}
    \item[Bug 3 --- \texttt{FreeQuantumState} non-subscriptable]: The initial implementation directly indexed \texttt{photon.quantum\_state[0]}, \texttt{photon.quantum\_state[1]}. SeQUeNCe's \texttt{FreeQuantumState} object does not support Python subscript notation, causing a \texttt{TypeError} on every measurement attempt and recording all trials as lost (zero sifted bits).

    \textit{Fix}: Replaced manual vector indexing with the standard \texttt{Photon.measure(basis\_matrix, photon, rng)} library call.
    
    \item[Bug 4 --- 4D$\to$2D dimension mismatch]: Two entangled photons share a 4-dimensional joint state vector in SeQUeNCe's state representation. Calling \texttt{Photon.measure} with a 2$\times$2 basis matrix on an uncollapsed joint state raised \texttt{matmul: size 4 is different from 2}.
    
    \textit{Fix}: \texttt{qsdet.get(photon)} is called \emph{first}: the \texttt{QSDetectorPolarization} model internally projects the joint 4D state onto a 2D subspace for the local photon. \texttt{Photon.measure} is then called on the already-collapsed, 2-dimensional state.
\end{description}

\subsection{Simulation Results --- Single-Hop Validation}

Validation parameters: 200 trials, 1 km fiber per link, attenuation 0.0002 dB/m, polarization fidelity 0.93, SPDC frequency 100 Hz.

\begin{itemize}
    \item \textbf{Sifted key length}: 80--110 bits ($\approx 45\%$ yield, theoretical max 50\%)
    \item \textbf{Agreement rate}: 93--99\%
    \item \textbf{Observed QBER}: 0--8\% (expected $\approx 7\%$ from $1 - p_{\text{fidelity}} = 0.07$)
\end{itemize}

The 5\% gap between observed and theoretical yield is attributed to fiber attenuation loss (2 dB over 1 km $\Rightarrow$ $P_{\text{trans}} \approx 63\%$ per photon, so some trials lose one photon and cannot be sifted). The QBER range arises from statistical sampling variance over small ($\approx$12 bit) QBER estimation samples.

A representative output:
\begin{lstlisting}[caption={Sample output: 200-trial BBM92 run}]

Total trials: 200

\subsubsection{Engine Selection via BFS Path Discovery}

The backend builds an adjacency graph from the quantum channel list and performs a BFS from each source node to Alice and Bob. The path length determines which engine is invoked:

\begin{lstlisting}[language=Python, caption={BFS path discovery on quantum channel graph}]
def _find_path_bfs(start_id, end_id, channels):
    adj = {}
    for ch in channels:
        if ch.type == 'quantum':
            adj.setdefault(ch.src, []).append(ch.dst)
            adj.setdefault(ch.dst, []).append(ch.src)
    visited, queue = {start_id}, [(start_id, [start_id])]
    while queue:
        curr, path = queue.pop(0)
        if curr == end_id:
            return path
        for nxt in adj.get(curr, []):
            if nxt not in visited:
                visited.add(nxt); queue.append((nxt, path + [nxt]))
    return None
\end{lstlisting}

If the discovered path has $\leq 2$ hops (direct link), the SeQUeNCe DES engine is used. If $> 2$ hops (multi-hop repeater), the physics-based Monte Carlo engine is invoked.

\subsubsection{Multi-Hop Quantum Repeater Engine}

The multi-hop engine simulates each hop independently using the Beer-Lambert attenuation model (Equation~\ref{eq:beer_lambert}). At intermediate repeater nodes, an additional 84\% memory coupling efficiency loss and a 2\% fidelity degradation per operation are applied. Entanglement swapping correlates the end-to-end Alice-Bob measurement outcomes:

\begin{lstlisting}[language=Python, caption={Per-trial multi-hop chain simulation}]
def simulate_path(path):
    survived, fidelity = True, 1.0
    for i in range(len(path) - 1):
        ch = ch_map.get(f"{path[i]}_{path[i+1]}")
        att_db = ch.attenuation * ch.distance
        trans  = 10 ** (-att_db / 10.0)
        if rng.random() > trans: return False, 0.0
        fidelity *= ch.fidelity
        if 0 < i < len(path) - 2:          # intermediate repeater hop
            if rng.random() > 0.84: return False, 0.0
            fidelity *= 0.98
    return survived, fidelity
\end{lstlisting}

\subsection{Bell State Measurement Node Protocol}

For direct topologies containing an intermediate BSM node, the \texttt{SimBSMProtocol} collects photons from two independent SPDC sources on the same trial index. When both arrive, a BSM outcome is drawn:

\begin{lstlisting}[language=Python, caption={SimBSMProtocol: joint Bell measurement}]
class SimBSMProtocol(Protocol):
    def received_message(self, src, msg):
        trial = msg.payload.get('trial')
        info  = SIMULATION_TRIALS.setdefault(trial, {})
        count = info.get('bsm_photon_count', 0)
        info['bsm_photon_count'] = count + 1
        if info['bsm_photon_count'] == 2:
            info['bsm_result'] = self.rng.randrange(4)
            # 0 = |Phi+>, 1 = |Phi->, 2 = |Psi+>, 3 = |Psi->
\end{lstlisting}

During post-processing, outcomes 1 ($|\Phi^-\rangle$) and 3 ($|\Psi^-\rangle$) trigger a classical bit correction on Bob's result: $b_B \leftarrow 1 - b_B$, restoring key correlation as derived from Equation~\ref{eq:swapping}.

\subsection{Multi-Hop Router Node Stack}

For SeQUeNCe-based multi-hop simulations, each intermediate node is instantiated as a \texttt{QKDRouterNode}—a custom \texttt{Node} subclass equipped with a \texttt{MemoryArray} and a rule-based resource management stack:

\begin{itemize}
    \item \textbf{\texttt{ResourceManager}}: Coordinates all entanglement-related protocols running at the node.
    \item \textbf{\texttt{MemoryManager}}: Tracks the state (\texttt{RAW}, \texttt{ENTANGLED}) and remote peer of each memory slot.
    \item \textbf{\texttt{RuleManager}}: Evaluates installed rules against current memory states and triggers protocol actions.
    \item \textbf{\texttt{EntanglementGenerationA}}: Drives heralded photon emission to the adjacent BSM node; updates memory state to \texttt{ENTANGLED} on a BSM success notification.
    \item \textbf{\texttt{EntanglementSwappingA}}: Fired by the rule manager when a node holds two memories entangled with its left and right neighbors. Performs a local BSM, sends the correction to the right node, and frees both memories.
    \item \textbf{\texttt{EntanglementSwappingB}}: Runs at the right end-node; applies the Pauli correction received from the swapping node to finalize the end-to-end entanglement.
\end{itemize}

\subsection{Physical Interpretation and Cross-Experiment Analysis}
% ---------------------------------------------------------------------------

\subsubsection{Repeater Advantage at Longer Distances}

The most significant result emerges in Experiment~2: at link distances of
approximately 15~km per direct hop, the 4-hop repeater configuration
yields \emph{more} sifted key bits (135 vs.\ 110) \emph{and} a lower QBER
(5.19\% vs.\ 7.27\%). This is the canonical demonstration of the quantum
repeater advantage and was not fully resolved in Experiment~1 due to the shorter
link distances.

The underlying physics is straightforward. Per-photon survival probability on the
direct 15~km link is:
\begin{equation}
    P_{\text{direct}} = 10^{-\alpha L / 10} = 10^{-0.0002 \times 15{,}000 / 10} \approx 0.501
\end{equation}
Both photons (to $A_2$ and $B_2$) must survive for a trial to be siftable, so the
joint probability is $P_{\text{direct}}^2 \approx 0.251$. In the repeater
configuration, each of the four links is approximately 7.5~km, giving:
\begin{equation}
    P_{\text{hop}} = 10^{-0.0002 \times 7{,}500 / 10} \approx 0.708
\end{equation}
The joint probability of two photons (each traversing one repeater hop) both
surviving is $P_{\text{hop}}^2 \approx 0.501$. Even after accounting for the
BSM swapping success probability (at most 50\% for linear optics), the
effective yield can exceed the direct-link joint survival probability when the
direct link is long enough. This crossover has been experimentally confirmed here.

In Experiment~1, the repeater QBER (6.90\%) exceeds the direct QBER (4.17\%)
because the cumulative fidelity product across four mismatched-fidelity links
($0.97 \times 0.95 \times 0.96 \times 0.97 \approx 0.859$) is lower than for the
two direct links, and entanglement swapping adds a non-zero BSM projection noise.

In Experiment~2, all quantum links share an identical fidelity of 0.98,
making the cumulative product for the four-hop chain
$0.98^4 \approx 0.922$, while the direct topology's two-link product is
$0.98^2 \approx 0.960$. The QBER difference is therefore smaller—and the
repeater's shorter individual hops provide better attenuation-corrected
per-photon survival, more than compensating for the higher BSM noise,
resulting in the observed inversion: lower QBER with the repeater.

\subsubsection{Security Assessment}

Both experiments satisfy the BBM92 security condition QBER $\leq 11\%$ for all
four configurations. No adversarial intervention is detectable in any run.
The BBM92 threshold is reached when photon loss forces a random-guess fallback
that introduces $\approx 25\%$ errors per lost photon pair; the observed QBER
values well below 11\% confirm that the channels are operating in the
physically realistic low-noise regime rather than the eavesdropping-induced
high-error regime.

    \item \textbf{Dual simulation engine}: Runtime-selected BFS-directed dispatch between a SeQUeNCe DES engine (direct links) and a Monte Carlo physics engine (multi-hop repeaters).

\subsection{Limitations and Future Work}

The current implementation has the following limitations that identify directions for future work:
\begin{itemize}
    \item \textbf{Error correction and privacy amplification}: The simulator currently outputs raw sifted keys. Implementation of Cascade error correction and two-universal hash privacy amplification is a natural next step.
    \item \textbf{Eavesdropping simulation}: No active Eve node is currently modeled. Adding intercept-resend and beam-splitting attack models would allow quantitative security analysis.
    \item \textbf{Decoherence modeling}: Quantum memory coherence time ($T_2$) limits are not currently enforced as a time-out condition on entanglement swapping chains. Long-latency paths may violate memory lifetime constraints in practice.
    \item \textbf{Quantum error correction}: Entanglement purification protocols (BBPSSW \cite{BBPSSW}) could be integrated to improve fidelity on noisy links before key distillation.
\end{itemize}

\section{Appendix A --- Theoretical Foundations}
\label{app:theory}

\subsection{Quantum Entanglement and Bell States}

A quantum system comprising two qubits (two-level quantum systems) spans a four-dimensional Hilbert space $\mathcal{H}_A \otimes \mathcal{H}_B$. The four maximally entangled Bell states form an orthonormal basis of this space:

\begin{align}
    |\Phi^+\rangle &= \frac{1}{\sqrt{2}}\bigl(|HH\rangle + |VV\rangle\bigr) \\
    |\Phi^-\rangle &= \frac{1}{\sqrt{2}}\bigl(|HH\rangle - |VV\rangle\bigr) \\
    |\Psi^+\rangle &= \frac{1}{\sqrt{2}}\bigl(|HV\rangle + |VH\rangle\bigr) \\
    |\Psi^-\rangle &= \frac{1}{\sqrt{2}}\bigl(|HV\rangle - |VH\rangle\bigr)
\end{align}

In the polarization encoding used by BBM92, $|H\rangle$ and $|V\rangle$ denote horizontal and vertical photon polarization states. A photon pair in the $|\Phi^+\rangle$ state, when measured by Alice and Bob in the \emph{same} polarization basis, always yields the same binary outcome (both $H$ or both $V$, with equal probability).

\subsection{Measurement Bases}

Two mutually unbiased bases are used:
\begin{itemize}
    \item \textbf{Z-basis (Rectilinear)}: $\{|H\rangle, |V\rangle\}$, corresponding to bit values $\{0, 1\}$.
    \item \textbf{X-basis (Diagonal)}: $\{|+\rangle = \frac{|H\rangle + |V\rangle}{\sqrt{2}},\; |-\rangle = \frac{|H\rangle - |V\rangle}{\sqrt{2}}\}$, also mapped to $\{0, 1\}$.
\end{itemize}

For a $|\Phi^+\rangle$ pair, same-basis measurements are perfectly correlated. Different-basis measurements yield completely uncorrelated results with probability $\frac{1}{2}$ each — these trials carry no key information and are discarded during sifting.

\subsection{Security of BBM92}

The security of BBM92 follows from the violation of Bell's inequalities by entangled quantum states. An eavesdropper Eve who intercepts a photon must perform a measurement, collapsing the entangled state and destroying the Alice-Bob correlations. This introduces detectable errors into the sifted key. The threshold QBER of 11\% corresponds to the maximum error rate consistent with no information leakage to a classical eavesdropper performing individual attacks.

\subsection{Spontaneous Parametric Down-Conversion}

The entangled photon source models SPDC in a Type-II nonlinear crystal (BBO). A pump photon at frequency $\omega_p$ and wavevector $\mathbf{k}_p$ is converted into a signal-idler pair:
\begin{align}
    \omega_p &= \omega_s + \omega_i \quad \text{(energy conservation)} \\
    \mathbf{k}_p &= \mathbf{k}_s + \mathbf{k}_i \quad \text{(momentum conservation / phase matching)}
\end{align}
Type-II phase matching produces orthogonally polarized signal and idler photons. With appropriate compensation optics, the output state is the maximally entangled $|\Phi^+\rangle$ Bell state. The number of pairs emitted per pulse follows a Poisson distribution with mean $\langle n \rangle = \eta P_{\text{pump}} / \hbar\omega_p$, where $\eta$ is the nonlinear conversion efficiency.

\subsection{Simulation Response Schema}

The response object contains:
\begin{itemize}
    \item \texttt{trials}: Array of per-trial objects with \texttt{trial}, \texttt{alice\_basis}, \texttt{bob\_basis}, \texttt{alice\_result}, \texttt{bob\_result}, \texttt{lossA}, \texttt{lossB}, \texttt{bsm} (if BSM node present), and \texttt{hops}.
    \item \texttt{siftedKeyAlice}, \texttt{siftedKeyBob}: Binary string representations of the sifted keys.
    \item \texttt{qber}: QBER as a percentage.
    \item \texttt{logs}: Array of human-readable simulation log strings.
    \item \texttt{alicePath}, \texttt{bobPath}: Lists of node IDs representing the discovered paths from source to Alice and Bob.
\end{itemize}

\begin{tabular}{cllc}
\toprule
\textbf{BSM Code} & \textbf{Projected Bell State ($T_1, T_2$)} & \textbf{A-B State} & \textbf{Bob's Correction} \\
\midrule
