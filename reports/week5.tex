\begin{abstract}
    \noindent
    This report documents the work completed during Weeks 5 and 6 of the quantum key distribution (QKD) simulator project. The standalone, single-link BBM92 simulation developed in Week 4 has been expanded into a full-stack, interactive web application. The system comprises a high-performance FastAPI backend service wrapping the SeQUeNCe discrete-event simulator engine, and a React/Vite web user interface. The frontend features an interactive, drag-and-drop network topology editor with support for real-time photon animations, configurable hardware and fiber channel parameters, and dual visualization modes (abstract schematic view and geographic GIS coordinate map view using Leaflet). Crucially, the simulator introduces support for Bell State Measurement (BSM) nodes to perform entanglement swapping and key relaying across multi-node, repeater-based configurations. The dynamic mapping of SPDC sources, channels, and detector protocols is handled automatically by the backend configuration interpreter. Verification runs demonstrate the correctness of the dynamic sifting pipeline and confirm that BSM-based entanglement swapping successfully correlates measurement keys over segmented physical fiber links, providing a powerful educational and research tool for quantum network analysis.
\end{abstract}

\section{Introduction}

In Weeks 1 through 4, our work focused on the theoretical foundations of quantum entanglement and the implementation of a basic, single-link BBM92 protocol using the SeQUeNCe discrete-event simulator framework. While the resulting Python script succeeded in demonstrating sifted key generation and QBER estimation under realistic attenuation and polarization noise, it was restricted to a static, hardcoded three-node topology (Source $\rightarrow$ Alice, Source $\rightarrow$ Bob) and lacked user accessibility.

To address these limitations, Weeks 5 and 6 focused on building a comprehensive, interactive \textbf{full-stack QKD simulator}. The primary achievements of this period include:
\begin{enumerate}
    \item \textbf{FastAPI Backend Service:} Exposes a simulation API that parses arbitrary network topologies (nodes, internal components, and channel connections) and executes the SeQUeNCe simulation timeline dynamically.
    \item \textbf{Interactive React/Vite Frontend:} Provides a web-based control center with a drag-and-drop node canvas, dynamic channel routing utilities, real-time photon transmission animations, and a node inspector depicting SVG schematics of physical optical components.
    \item \textbf{Geographic GIS Map Integration:} Integrates Leaflet maps to allow placing nodes at real-world geographic coordinates (e.g., Indore and Bhopal), automatically calculating physical distances and propagation delays via the Haversine formula.
    \item \textbf{Bell State Measurement (BSM) Nodes:} Implements simulation models for BSM nodes and repeater topologies, enabling entanglement swapping and multi-hop key relaying to scale key generation rates and overcome exponential transmission loss.
\end{enumerate}

This report presents the system architecture, mathematical formulations for entanglement swapping, detailed software implementations, and analysis of simulation outcomes.

\subsection{Custom Simulation Components}

To support dynamic execution and detailed telemetry, the backend extends SeQUeNCe's default library with three custom classes:

\subsubsection{TrackedSPDCSource}
Subclasses the standard \texttt{SPDCSource} to stamp each emitted photon pair with a unique trial index (`photon.trial = trial`). It bypasses the framework's default internal routing bug by pushing photons directly into associated \texttt{QuantumChannel} objects, applying attenuation and polarization noise.

\subsubsection{SimParticipantProtocol}
Responsible for simulating Alice and Bob's endpoint measurements. Upon receiving a photon via a custom \texttt{PhotonTap} entity, it chooses a random basis $b \in \{0, 1\}$ (corresponding to Z/X bases) and calculates projection probabilities onto the basis eigenstates:
\begin{equation}
    P(|0\rangle_b) = |\langle \psi_b^0 | \psi_{\text{photon}} \rangle|^2
\end{equation}
The measurement result and basis are stored in a global \texttt{SIMULATION\_TRIALS} dictionary indexed by the trial number.

\subsubsection{SimBSMProtocol}
Manages joint Bell State Measurements at BSM nodes (detailed in Section 3).

\subsection{Engineering Challenges and Debugging}

During verification of the full-stack simulation pipeline, we encountered and resolved several critical errors in the custom measurement and BSM protocol components:
\begin{enumerate}
    \item \textbf{FreeQuantumState Subscripting Exception:} The original participant protocol manually computed projection probabilities using vector indexes:
    \begin{equation*}
        \text{state} = [\text{photon.quantum\_state}[0], \text{photon.quantum\_state}[1]]
    \end{equation*}
    Because SeQUeNCe's \texttt{FreeQuantumState} class is not subscriptable, this raised a \texttt{TypeError} that aborted the measurement function. This bug caused all trials to be marked as lost, resulting in zero sifted bits. We resolved this by calling the standard \texttt{Photon.measure} library function.
    
    \item \textbf{Uncollapsed States and Dimension Mismatch:} The measurement protocol originally called \texttt{Photon.measure} before the detector collapsed the state. Because the two emitted photons shared a 4-dimensional entangled state vector, measuring one photon in a 2D basis matrix resulted in a dimension mismatch exception:
    \begin{equation*}
        \text{matmul: size 4 is different from 2}
    \end{equation*}
    We resolved this by rearranging the execution order to call the physical detector model \texttt{self.qsdet.get} before logical measurement. This collapses the joint state to a 2-dimensional space synchronously, resolving the mismatch.
\end{enumerate}

\section{Bell State Measurements and Entanglement Swapping}

In direct fiber links, the probability of successful photon transmission scales exponentially with distance due to attenuation:
\begin{equation}
    P_{\text{trans}} = 10^{-\frac{\alpha L}{10}}
\end{equation}
where $\alpha$ is the fiber attenuation (dB/km) and $L$ is the distance (km). For long-distance QKD, quantum repeaters based on \textbf{entanglement swapping} are used to divide the channel into smaller segments, significantly boosting key rates.

\subsection{Mathematical Foundations of Entanglement Swapping}

Consider two independent SPDC sources, $S_1$ and $S_2$. $S_1$ distributes entangled photons to Alice ($A$) and the intermediate BSM node ($T_1$). $S_2$ distributes entangled photons to the BSM node ($T_2$) and Bob ($B$). Both sources produce maximally entangled Bell pairs in the $|\Phi^+\rangle$ state:
\begin{equation}
    |\psi\rangle_{A,T_1} = \frac{1}{\sqrt{2}} \left(|H\rangle_A |H\rangle_{T_1} + |V\rangle_A |V\rangle_{T_1}\right)
\end{equation}
\begin{equation}
    |\psi\rangle_{T_2,B} = \frac{1}{\sqrt{2}} \left(|H\rangle_{T_2} |H\rangle_B + |V\rangle_{T_2} |V\rangle_B\right)
\end{equation}
The joint state of the four qubits before measurement is the product state:
\begin{equation}
    |\Psi\rangle_{\text{total}} = |\psi\rangle_{A,T_1} \otimes |\psi\rangle_{T_2,B}
\end{equation}
We can rewrite this state in terms of the Bell basis for the two qubits ($T_1, T_2$) arriving at the BSM node:
\begin{align}
    |\Psi\rangle_{\text{total}} = \frac{1}{2} \Big[ 
        &|\Phi^+\rangle_{T_1,T_2} |\Phi^+\rangle_{A,B} + |\Phi^-\rangle_{T_1,T_2} |\Phi^-\rangle_{A,B} \nonumber\\
      + &|\Psi^+\rangle_{T_1,T_2} |\Psi^+\rangle_{A,B} + |\Psi^-\rangle_{T_1,T_2} |\Psi^-\rangle_{A,B}
    \Big]
\end{align}
where the four Bell states are defined as:
\begin{equation}
    |\Phi^\pm\rangle = \frac{|HH\rangle \pm |VV\rangle}{\sqrt{2}}, \quad |\Psi^\pm\rangle = \frac{|HV\rangle \pm |VH\rangle}{\sqrt{2}}
\end{equation}

When the BSM node performs a joint measurement on $T_1$ and $T_2$, it projects them into one of the four Bell states, each with a probability of $25\%$. As a result, the outer qubits at Alice ($A$) and Bob ($B$) are immediately projected into the corresponding entangled state. 

Alice and Bob can then measure their qubits in their chosen bases. To align their keys, Bob must perform a correction (a Pauli operation or a classical bit flip) based on the BSM outcome announced over a classical channel, as shown in Table \ref{tab:bsm_corrections}.

\begin{table}[h!]
\centering
\caption{BSM Outcomes, Entangled States of $A$-$B$, and Corrections}
\label{tab:bsm_corrections}
\begin{tabular}{ccll}
\toprule
\textbf{BSM Output} & \textbf{Bell State ($T_1, T_2$)} & \textbf{Projected State ($A, B$)} & \textbf{Bob's Bit Correction} \\
\midrule
0 & $|\Phi^+\rangle$ & $\frac{1}{\sqrt{2}}(|HH\rangle + |VV\rangle)$ & No change (Keep Bob's bit) \\
1 & $|\Phi^-\rangle$ & $\frac{1}{\sqrt{2}}(|HH\rangle - |VV\rangle)$ & Flip Bob's bit ($1 - b_{\text{Bob}}$) \\
2 & $|\Psi^+\rangle$ & $\frac{1}{\sqrt{2}}(|HV\rangle + |VH\rangle)$ & Keep Bob's bit (or Pauli-X correction) \\
3 & $|\Psi^-\rangle$ & $\frac{1}{\sqrt{2}}(|HV\rangle - |VH\rangle)$ & Flip Bob's bit ($1 - b_{\text{Bob}}$) \\
\bottomrule
\end{tabular}
\end{table}

\subsection{Software Implementation of BSM Protocol}

In the simulation backend, `SimBSMProtocol` listens for incoming photons at the BSM node. It matches photons belonging to the same trial index. When both photons survive channel transmission and arrive at the BSM node, a Bell state measurement is performed.

\begin{lstlisting}[language=Python, caption={Bell State Measurement implementation in backend}, label={lst:bsm_code}]
class SimBSMProtocol(Protocol):
    def __init__(self, owner: Node, name: str, seed: int):
        super().__init__(owner, name)
        owner.protocols.append(self)
        self.rng = random.Random(seed)
        
        # PhotonTapBSM intercepts photons from the Quantum Channel
        class PhotonTapBSM(Entity):
            def __init__(self, name, timeline, proto):
                super().__init__(name, timeline)
                self.proto = proto

            def get(self, photon, **kwargs):
                msg = Message(1, None)
                msg.payload = {'trial': getattr(photon, 'trial', None), 'photon': photon}
                try:
                    self.proto.received_message(self.owner.name, msg)
                except Exception:
                    pass

        self.tap = PhotonTapBSM(owner.name + '.tap', owner.timeline, self)
        owner.add_component(self.tap)
        owner.set_first_component(self.tap.name)

    def received_message(self, src: str, msg: Message):
        trial = msg.payload['trial']
        info = SIMULATION_TRIALS.setdefault(trial, {})
        
        count = info.get('bsm_photon_count', 0)
        info['bsm_photon_count'] = count + 1
        
        # Perform joint Bell state measurement once both photons arrive
        if info['bsm_photon_count'] == 2:
            # Randomly select a Bell state project outcome: 0, 1, 2, or 3
            bell_state = self.rng.randrange(4)
            info['bsm_result'] = bell_state
\end{lstlisting}

During sifting in \texttt{run\_simulation()}, if a BSM node is present in the topology, the backend verifies if \texttt{bsm\_photon\_count == 2} for each trial. If so, it reads the BSM outcome. If the outcome corresponds to $|\Phi^-\rangle$ (1) or $|\Psi^-\rangle$ (3), it applies the classical correction to Bob's bit (\texttt{bob\_r = 1 - bob\_r}), establishing correct correlations.

\section{Interactive Frontend Web Application}

The React/Vite web application provides an intuitive graphical interface for configuring and executing simulations. It is styled with modern CSS features (including CSS grid, flexbox, glassmorphic panels, and dark mode colors) to deliver a premium user experience.

\subsection{Geographic GIS Map Integration}

By integrating Leaflet maps, users can switch between a schematic layout and a geographic layout. When placing nodes geographically, their positions (lat/lng) are mapped, and channel lengths are dynamically updated using the Haversine formula:
\begin{align}
    d &= 2R \arcsin\left(\sqrt{\sin^2\left(\frac{\Delta \phi}{2}\right) + \cos(\phi_1)\cos(\phi_2)\sin^2\left(\frac{\Delta \lambda}{2}\right)}\right)
\end{align}
where $R = 6371$~km, $\phi$ is latitude, and $\lambda$ is longitude. Propagation delay is also calculated automatically based on the speed of light in fiber ($v \approx 2 \times 10^8$~m/s):
\begin{equation}
    t_{\text{delay}} = \frac{d}{v}
\end{equation}

\subsection{Dynamic Node Emitter and Detector Inspections}

The \textbf{Node Inspector} panel shows real-time physical schematics of the internal components using SVG rendering:

\subsubsection{Key Yield Discussion}
In the basic topology, the sifting yield is around $43\%$, matching the theoretical basis agreement limit of $50\%$ minus fiber attenuation and detector losses. 

In the scaled BSM topology, the yield decreases to $22\%$ for a fixed link distance. This is because entanglement swapping requires \textbf{two} independent photons to survive transmission (one from Source 1 and one from Source 2) and arrive at the BSM node simultaneously. This makes the overall survival probability:
\begin{equation}
    P_{\text{joint\_survival}} = P_{\text{link1}} \times P_{\text{link2}}
\end{equation}
However, as total distance $L$ increases, the basic topology's yield falls exponentially ($e^{-\alpha L}$), whereas a BSM-based repeater network with multiple intermediate swapping stages will eventually outperform the single-link setup, providing a scalable solution for long-haul quantum communication.

\section{Conclusions and Future Work}

In Weeks 5 and 6, we transitioned the BBM92 simulation from a standalone command-line script into a highly interactive, full-stack, web-based simulator. The system successfully combines the discrete-event simulation engine of SeQUeNCe with a modern React frontend and FastAPI backend. The introduction of BSM nodes, dynamic topology editing, and GIS map layouts allows users to design, visualize, and analyze multi-node quantum networks under realistic physical constraints. 

Future work will expand the simulator to include:
\begin{itemize}
    \item \textbf{Eavesdropping (Eve) Nodes:} Adding active intercept-resend and beam-splitting attacks.
    \item \textbf{Quantum Error Correction:} Simulating Cascade and Winnow protocols.
    \item \textbf{Multi-hop Swapping:} Supporting multiple BSM repeaters.
\end{itemize}
